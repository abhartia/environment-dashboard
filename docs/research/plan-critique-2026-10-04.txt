[blocker] (Provenance model: licence classes; Repo layout (data/ committed); Architecture ()
PROBLEM: The plan cannot enforce 'display-only, no download' as designed. The pipeline output, data/indicators/<id>.{json,csv}, catalog.json and SHA256SUMS, is committed to a public GitHub repo. Interactive islands fetch /data/*.json. Each quarterly release is archived to Zenodo through the GitHub integration. So the values of every display-only, ND, NC and SA source would be redistributed in bulk, in machine-readable form, permanently (git history and a Zenodo DOI cannot be withdrawn cleanly). That includes Poore & Nemecek, ICCT, the IPCC WGIII statements, Carbon Brief, UNEP and CAT. The Zenodo snapshot would also carry the repo's MIT/CC BY licence metadata, and LICENSE-CONTENT (CC BY 4.0) would appear to cover pages that embed NC-SA charts (Lancet) and BY-SA charts (LPI).
FIX: Add a rule to the Provenance model. Indicators in classes display-only, nd and custom-no-rehost are never written to the committed data/ tree, /data/*.json, datapackage.json or the Zenodo deposit. The build reads them from envdash-private (R2 credentials in CI) and renders them as server-side HTML text and SVG only. data/ commits only their sha256 and citation metadata. A check-build rule fails if any file under data/ or out/data/ belongs to those classes. Each resource in datapackage.json and the Zenodo deposit declares its own licence (the per-resource 'licenses' field), and the Zenodo deposit excludes non-redistributable resources. LICENSE-CONTENT should read: 'Site text CC BY 4.0, except figures and data, which carry the licence shown in their footer.'

[major] (Data catalogue › Consequences › Ocean and ice (GMSL); Architecture: R2 envdash-p)
PROBLEM: The plan treats AVISO+ GMSL as open-attribution, which would mirror the raw file publicly. AVISO's licence is custom and explicitly not CC BY. §3.2 forbids sharing the original, unmodified product through a web portal, public API or cloud without CNES's written authorisation. The plan's public bucket (files.environmentdashboard.org), the 'Original file' and 'Archived copy' actions, and the SPN2 capture of the file URL would each breach it. A homepage headline is also at risk: an OLS fit on the TXT gives 3.41 mm/yr, but AVISO publishes 3.6 ± 0.3 mm/yr, because the TXT may lack the TOPEX-A and radiometer drift corrections. Finally, the NASA-SSH 'PD twin' and Frederikse are Earthdata Login-gated, and no credential is planned for them. Frederikse's public-domain status is also not airtight: the Zenodo copy is 'other-closed'.
FIX: Create the licence class custom-attribution-no-rehost. Put the AVISO raw file in envdash-private, publish only its sha256, and link 'Original file' to the AVISO URL. Downloads may serve only derived series, with the AVISO licence link and a 'modified by Environment Dashboard' note (§3.1). For the headline rate, either quote AVISO's 3.6 ± 0.3 mm/yr as a published-value with page and date, or label 3.41 as 'our OLS on the AVISO file' and explain the gap. Add an Owner action: create an Earthdata Login and store it in Keychain as `earthdata-envdash`, plus a CI secret. Make NASA-SSH (CC0 per the Earthdata guidance page) the public-mirror series.

[major] (Data catalogue › Baselines; Consequences › Temperature ('HadCRUT5.2 … GISTEMP v4)

Show the baseline method in the chart legend and in the Trace panel. If a WMO-consistent comparison is wanted, add it as a separate, labelled series.

[major] (Architecture > Hosting; Repo layout > 'Copy verbatim from gigabiome ... public/_)
PROBLEM: The plan moves hosting to Workers Static Assets but still copies gigabiome's Pages-only files verbatim. The owner has never shipped on Workers. gigabiome uses Pages direct upload, and wadecv and simmerlist use no Workers at all. Workers does not reproduce Pages defaults, and the plan has no wrangler config that would cover the gaps. (1) Workers does not detect 404.html on its own: without `not_found_handling: "404-page"`, a missing URL gets a bare 404 with no page. (2) gigabiome's `_headers` noindex rules match `https://:project.pages.dev/*`, so they never match a workers.dev host. (3) Cloudflare adds noindex automatically only to workers.dev *Preview* URLs. The production `<worker>.<sub>.workers.dev` host is a full, indexable duplicate of the site. (4) Trailing-slash redirects on Workers are 307. (5) Nothing Workers-only is used: there is no Worker script and no cron, and asset requests are free on both platforms. So Workers adds new failure modes for no benefit to this site.
FIX: Lower-risk choice: keep Cloudflare Pages direct upload for v1. Copy deploy-web.yml and _headers verbatim, changing only the project name and adding the .org apex as a Pages custom domain. Migrating to Workers later is a config-only change. If Workers stays, do all of the following. (a) Add `wrangler.jsonc` to the repo layout with `{name, compatibility_date, assets:{directory:"web/out", html_handling:"auto-trailing-slash", not_found_handling:"404-page"}, routes:[{pattern:"environmentdashboard.org", custom_domain:true}], workers_dev:false}`. (b) Move `public/_headers` and `deploy-web.yml` from the 'verbatim' list to 'adapt'. Replace the pages.dev rules with `https://:version.:subdomain.workers.dev/*  X-Robots-Tag: noindex`. (c) Add a check-build assertion that this rule exists. (d) Add a post-deploy check that a missing URL returns 404 with the custom 404 page body.

[major] (Provenance model ('processing steps with script path + git SHA'); Verification ()
PROBLEM: These three choices conflict. An export cannot contain the SHA of the commit that adds it. If the commit SHA is embedded, the golden test re-runs on commit C, produces C's SHA, and never matches the bytes committed from the parent commit. Rebuilds are also keyed only on upstream ETag/Last-Modified. A transform-code change therefore never triggers a rebuild, so committed data/ silently drifts from the code that claims to have produced it. If the fix is to rebuild everything on every run, every file is rewritten each week. That churns git, moves sitemap lastmod and spams IndexNow, which repo_gigabiome.json notable_lessons warns 'taught bingbot to ignore simmerlist'.
FIX: Change the processing record to `{script: path, transform_sha256: sha256 of the transform module source, lock_sha256: sha256 of uv.lock, inputs: [snapshot sha256…]}`, and leave the commit SHA out of exported bytes. Make the rebuild key `(input snapshot sha256s, transform_sha256, lock_sha256)`, so code changes rebuild exactly the affected indicators. The golden test recomputes that key and the bytes. Put the release-level commit SHA only in `datapackage.json` / the Zenodo release, which are written after the commit.

[major] (Information architecture > Country lens ('?in=DEU ... every story shows that cou)
PROBLEM: In a static export, the server-rendered HTML cannot see `?in=`. Reading the page's `searchParams` prop makes the route dynamic, which output:export rejects. That leaves `useSearchParams` in a client component, and the build fails unless that component sits inside a Suspense boundary; whatever is inside the boundary renders as its fallback in the HTML. So: (1) every server-rendered SVG chart stays world-only, and each story chart needs a second, client-side renderer for the lens; (2) a page-level Suspense wrapper would blank the HTML, breaking LCP-is-text, no-JS reading and check-build's one-h1 rule; (3) server-rendered internal links do not carry `?in=`, so the lens is lost on every click unless every nav link becomes a client component; (4) `router.push` with a new query string re-fetches the RSC payload.
